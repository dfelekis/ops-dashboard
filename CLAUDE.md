## What this is

Operations dashboard for a fictional coffee-equipment company (Marlowe & Finch): a read-only Spring Boot JSON API over PostgreSQL plus a no-build vanilla-JS page. The repo is also a workshop kit (`workshop/`, `docs/tickets/`, `docs/examples/`); the README's top half is workshop material, the "The app" half describes the code. Tickets (`docs/tickets/TODO-231..233`) describe the planned work.

## Commands

```bash
docker compose up -d db                      # PostgreSQL 16 on :5432 (db/user/password "ops")
./mvnw spring-boot:run                       # app on http://localhost:8080 (postgres profile, default)
SPRING_PROFILES_ACTIVE=demo ./mvnw spring-boot:run   # in-memory H2, no Docker needed

./mvnw test                                  # Java tests (JUnit 5, MockMvc, always on H2)
./mvnw test -Dtest=DashboardRepositoryTest   # one class; add #method for a single test
npm install && npm test                      # Jest + jsdom frontend tests
npx jest src/test/javascript/render.test.js  # one frontend test file
```

There is no linter or formatter configured. `docker compose down -v` wipes the database; Flyway re-seeds on next start. Connection overrides: `DATABASE_URL`, `DATABASE_USER`, `DATABASE_PASSWORD`.

## Architecture

- **Backend** (`src/main/java/com/marlowefinch/ops/`): flat package. Each `*Controller` exposes GET endpoints under `/api` and calls `DashboardRepository` or `VendorRepository`, which run plain SQL via Spring JDBC (no JPA/ORM) and map rows into small response records (`Kpis`, `CarrierOnTime`, `LateDelivery`, `TicketCategoryCount`, `Vendor`). `from`/`to`/`limit` query params default to the last 30 days ending "today" and are resolved by `DateRange.resolve`, which deliberately does no validation yet (bad dates are a 500; see TODO-232).
- **Pinned clock:** "today" is `ops.today=2026-09-21` (bean in `ClockConfig`), not the system date. Seed data covers the 90 days before it, and default ranges, "days until renewal" and tests all depend on it. Use the injected `Clock`, never `LocalDate.now()`.
- **Database:** Flyway migrations in `src/main/resources/db/migration/` (`V1__schema.sql`, `V2__seed.sql`) must run unchanged on both PostgreSQL and H2 (PostgreSQL mode), so keep SQL portable. `V2__seed.sql` is generated by `tools/make_seed.py`; regenerate rather than hand-edit (it also writes `docs/data/` CSV and a git-ignored answer key).
- **Profiles:** `postgres` is the default (`spring.profiles.default`); `demo` uses H2. Tests always use H2.
- **Frontend** (`src/main/resources/static/`): `index.html`, `app.js`, `style.css` served directly by Spring. `app.js` fetches the endpoints for a date range and renders KPI tiles, two hand-built inline-SVG charts, a late-deliveries table and a vendor list. Colours are hardcoded in `style.css` and in the SVG code (relevant to the TODO-231 theme-toggle ticket).
- **Frontend tests** (`src/test/javascript/`): `setup/loadApp.js` loads `index.html` into jsdom, fakes `fetch` for every `/api` endpoint, and runs `app.js`. It keeps `REGISTERED_IDS`, a list of every element id in `index.html`; `harness.test.js` fails if `index.html` gains an id not in that list, so update the harness when adding interactive elements.

## Conventions and constraints

- `pom.xml` dependencies are frozen (comment at the top of the file): changes require a CHG ticket. Do not add dependencies casually.
- There is no CI wired up; `docs/examples/ci.workflow.yml` is a template to copy into `.github/workflows/`.
- `.mcp.json` registers a read-only `postgres` MCP server against the local compose database (`postgresql://ops:ops@localhost:5432/ops`).
